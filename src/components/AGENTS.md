# Component rules
- StaffTable receives only caller-filtered rows and projected cells; hosts retain authorization, status derivations, editor state and mutation handlers; shared queue/dashboard/chart hosts opt into table-only presentation. Expanded details stay host-owned. Why: sorting, saved views and paging must not reveal excluded data, duplicate audits or change excluded surfaces.
- TaskQueueCard owns an actor-keyed, session-only editor cache; TaskWorkRow may retain drafts there across table unmounts, and Worklist derives its displayed statistics from the selected caller-filtered view. Why: paging must not discard unfinished input or imply counts for a different view, and role changes must not reuse another actor's draft.
- Public website text is isolated in `i18n.website.ts`; public header/footer/crisis support live in `WebsiteLayout`, branding uses `WebsiteBrand` and navigation uses `WebsiteNavigation`; `WebsiteContent` shares the closing CTA and owns About/Team content, while application branding stays unchanged. Why: the public brand and future logo must never rename patient or staff experiences.
- Public scroll state and measured crisis/header/demo clearance belong to WebsiteLayout; WebsiteNavigation renders one shared bilingual menu inventory as click-open desktop categories with hover/focus flyouts and nested phone accordions in a Radix Dialog sheet with measured crisis clearance; WebsiteBrand uses an unchanged extracted supplied symbol and live public wordmark. Why: public navigation and safe viewport clearance stay consistent without changing member/staff shells or existing resource access.
- Every staff "+ New" launcher uses NewActionMenu with registry-filtered inputs and keeps its own action handlers; patientless pages reuse DashboardActionLauncher (patient picker first, no shortcuts); a role with no permitted item renders no trigger; a trigger leaves the shell slot once its page is navigated away. Why: one menu, no duplicate actions, no granted permissions, no stale buttons.
- Public WebsitePage owns bilingual breadcrumbs/header/ReadyBand; JourneyPage consumes baseline-title data and PublicDirectory consumes only publicDirectory projections. Resource ContentForm exposes showOnPublic/county through existing reasoned content actions; public reports are a separate labelled review section in ResourceVerificationQueue. Why: templates and public reports must not duplicate resources or change member shells and verification gates.
