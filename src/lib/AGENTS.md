# Architecture rules (src/lib and the screens that call it)

- The 24-hour late-cancel check lives only in `src/lib/lateCancel.ts`; `SchedulingConstraints.isLateCancel` and the store both call it — one rule, no store↔scheduling import cycle.
- Visit cancel / no-show go through `staffCancelAppointment`, `markAppointmentNoShow`, `patientRequestCancel` / `advocateRequestCancel` + `resolveCancelRequest` in `ehr.ts` — never set `status` directly from UI; a cancelled or no-show visit can never open a claim.
- Group join goes through `requestJoinGroup` / `approveGroupJoinRequest` / `declineGroupJoinRequest` in `ehr.ts`; patients never self-enroll from the UI. Why: every join is reviewed, telehealth-consent-checked and audited.
- The chart ASAM section is gated by `roleSeesAsamSection` (asamReporting.ts); Part 2 sections are hidden, not locked-stubbed (`recordSectionGate.ts`). Why: menu and ?section= URL must agree with the ASAM task gate.
- Inbox claim / assign / done / reopen / make-a-task go through `src/lib/inboxActions.ts`, which checks roles, and nowhere else. Why: only roles that can already see an item may act on it or be assigned it, and protected items stay generic in labels, audit rows and task text.
- Clinical Coordination actions (reassign, cancel, rebook, profile, freeze) go through `src/lib/coordination.ts`; only `clinical_coordinator` / `sys_admin` (`coordinationRoles.ts`, nav gate `coordination_desk`). Why: every coordinator decision is role-checked, reasoned, Part 2-safe in notifications and audited.
- Weekly caseload review (contacts, draft cadence, week sign-off, coordinator roll-up) lives only in `src/lib/caseloadReview.ts`, gated by `caseloadRoles.ts`. Why: one configurable draft cadence; staff summaries read only PHQ-2/GAD-2 quick checks, never the patient-private mood store, and never show scores or note text in the roll-up.
- Staff screens read the patient-private mood store only through `src/lib/moodCheckInCount.ts` (a day count, nothing else). Why: case managers may see participation, never mood content.
- Staff message masking (`careMessageMasking.ts`) hides SUD-flagged bodies from roles whose `screeners_sud` access is locked OR "none". Why: roles with no Part 2 access at all were previously unmasked.
- SUD-medication detection lives only in `src/lib/sudMedClassifier.ts` (drug list + order `sudRelated` toggle); every staff medication surface filters through `filterSudMedsForRole` (asamReporting.ts). Why: one Part 2 rule, no surface-by-surface regexes.
- Signed progress notes change only via `addNoteAddendum` / `amendProgressNote` / `requestNoteVoid` + `decideNoteVoid` in `ehr.ts` (rules in `noteRevisions.ts`); claims react through the `onNoteRevised` claim bridge. Why: the signed body is never edited in place, and every revision is versioned, audited and billing-safe.
- Patient demographics change only via `updatePatientDemographics` (rules in `demographics.ts`). Why: reason-gated identity fields, kept history, eligibility re-check flag.
- Order signing safety (allergy/NKDA/CURES) lives in `src/lib/orderSafety.ts` and is enforced by `orderSigningBlocker` inside `signOrders` whenever an `actorRole` is passed (every staff UI does; module-load seeds don't). Why: one rule for UI and store.
- Outpatient episodes and higher-level-of-care referrals live only in `src/lib/outpatientCare.ts`, separate from in-facility pre-release episodes; SUD rows masked via `roleSeesAsamSection`. Why: Part 2-safe, audited, no change to pre-release flow.
- Patient voice (read aloud / answer by voice) lives only in `src/hooks/useAdelVoice.ts` + `src/lib/adelVoice.ts` + `src/components/voice/`; sensitive steps are tap-only via `isTapOnlyStep`, validated screeners read verbatim. Why: one reusable voice layer; no audio stored, only confirmed text.
- Legal Part 2 disclosures (recipient, purpose, revoke) live in `outpatientCare.ts` (`recordLegalDisclosureConsent` / `revokeLegalDisclosure`) on top of the consent store. Why: a disclosure recorded on a referral shows and revokes on the consent screen.
- The `physician` role inherits every PMHNP grant through `permissionRole()` in `roles.ts` (matrix stored once under `pmhnp`); role lists name both. Why: the two can never drift apart.
- Refill review enforces prescriber-only approval, a CURES step for controlled/MOUD/SUD meds (`refillNeedsCures`) and a required deny reason inside `reviewRefill` whenever `actorRole` is passed. Why: same rule as new orders, in the store not the UI.
- In-facility / inpatient surfaces (MAR, shift count, pre-release, custody, facility protocols, NCCHC tiles) sit behind the single `inFacilityEnabled()` flag in `src/lib/inFacility.ts`, off by default. Why: Adelante is outpatient-only; code and tests are kept, higher-level referrals are not gated.
- Chart Tracking reads only `src/lib/trackingTimeline.ts` (screenerHistory + missedScreeners + signed ASAM level); SUD instruments are removed for roles failing `roleSeesSudInstruments`. Why: one source for Tracking and the care plan, one Part 2 rule.
- The structured care plan (problems, goals, assignments, Adel suggestions, review/sign/acknowledge) lives only in `src/lib/structuredCarePlan.ts`; old plain goals migrate into it on read and SUD-linked items filter through `staffPlanView`. Why: one model for the staff editor and patient "My plan", Part 2-safe.
- The simulated HIE feed (outside encounters, Adel follow-up drafts, outside meds, utilization) lives only in `src/lib/hie.ts` behind the mock adapter `src/lib/vendors/hie.ts`; every surface shows `HIE_LABEL`, SUD records without consent are held and received ones gated by `roleSeesAsamSection`. Why: nothing changes the record automatically and Part 2 stays one rule.
- The HIE operations hub (matching queue, outbound log, demo seed) lives in `src/lib/dataExchange.ts` on top of `hie.ts`; access only via `DATA_EXCHANGE_ROLES` (sys_admin, clinical_coordinator). Why: unmatched records never reach a chart and every hub action is audited.
- Chart create/act actions live only in `src/lib/chartActions.ts`; each `allowed()` calls the store's own check (never a new role list) and chart sections show only when the role can view or act. Why: menu, buttons and store can't disagree; `chartActionsConsistency.test.ts` attempts every store call per role.
- Lab orders (placeholder, not sent), screener requests and metabolic measures live only in `src/lib/chartOrders.ts`; the "+ New" launcher (`ChartActionLauncher.tsx`) is built only from `CHART_ACTIONS`. Why: one role/Part 2 rule (UDS and AUDIT/DAST-10 gated) shared by menu, shortcuts and store.
- The chart header, alerts, Adel Brief, sticky note and Brief landing tab derive only from `src/lib/chartBrief.ts`, reusing existing Part 2 filters (trackingTimeline, hieChartView, filterSudMedsForRole, chartOrders); Brief/header buttons open "+ New" drawers via `chartActionBus.ts`. Why: one derived source, no new masking rules, registry stays the gate.
- Chart tabs are an arrangement only: `src/lib/chartTabs.ts` maps section ids to 8 tabs and resolves every `?section=` value (tab id, section id, old alias); sections keep their ids and gates. Why: every existing link keeps working and no access rule moves.
- Role-based first sub-section per chart tab lives only in `roleFirstSections` / `orderSectionsForRole` (`chartTabs.ts`); it reorders, never gates. Why: arrangement stays separate from access rules.
- The clinician workspace reads one person only: `resolveWorkspaceActor` in `src/lib/workspaceIdentity.ts` (acting staff, or an audited "View as" for coordinator / sys_admin / supervisor). Why: widgets and counts can never disagree about whose day it is.
- Visit check-in / attended / staff reschedule go through `checkInAppointment` / `markAppointmentAttended` / `staffRescheduleAppointment` in `ehr.ts`; only "attended" can bill (`NON_BILLABLE_VISIT_STATUSES`). Why: same role check and audit as no-show.
- CURES is required only for controlled substances (DEA II–V) via `requiresCuresCheck`; SUD-med masking stays in `sudMedClassifier.ts`. Why: naltrexone/acamprosate/disulfiram are Part 2 but not controlled.
- Demo seed visit times use `src/lib/demoTime.ts` (Pacific business hours), never `Date#setHours`. Why: the server clock is UTC.
- Standing "Simulated" rule: until a persistent backend, security controls and BAA-covered vendors exist, every placeholder / mock / demo integration (HIE, eligibility, CURES, eRx, labs, telehealth, CalOMS/ISL export, voice, Adel drafts, SMS/email, payments/clearinghouse, anything under `vendors/`) has a `simulated: true` flag in `features.ts`; registry actions depending on it are simulated via `actionIsSimulated` (runAction.ts), audit `simulated: true` (never plain "succeeded") and show `confirmationFor()` "Simulated" text; placeholder audit categories get `simulated: true` in `appendAudit`. Why: nobody mistakes a demo integration for a live one; `mergeFinishSimulated.test.ts` enforces it.
- Merged-away items carry a Part 2 hold (`src/lib/mergePart2.ts`) decided only by structured classification (`classifyPart2`: SUD flags, `sensitive`, category, instrument, med classifier) — never text; unclassified = held. Released only by `reconfirmConsentAfterMerge` via `runAction`. Why: a merge never extends Part 2 consent.
- Staff exact-match "Create anyway" and HIE match decisions run only through `runAction` (`patient_create_anyway`, `hie_match_decide`). Why: permission-checked and audited like every registry action.
- Billing / admin / coordinator "+ New" is built only from `CHART_ACTIONS` entries with `opsMenu` (`OpsActionLauncher.tsx`); roadmap items are `pending` + `comingSoon` (shown disabled). Billing/admin counts come only from `src/lib/billingWorkspace.ts` with billing-safe block labels. Why: strip, tiles and menu can't disagree and no clinical detail reaches billing.
- Feature flags change only via `setFeatureFlagWithReason` through `runAction("feature_flag_set")` (sys_admin, reason required); simulated flags can never go live. Why: every switch change is audited and the Simulated rule can't be bypassed.
- Provider & site reference (Organization → Sites → Programs, county/program config) lives only in `src/lib/providerReference.ts`; practitioner NPIs are read from the staff roster, never stored twice. Why: one future MPF/274 match point.
- FSP presumptive eligibility lives only in `src/lib/fspEligibility.ts`, gated by `isJusticeInvolved` + the existing `custody_tracking` class. Why: no role widened, staff-only.
- AFBI field outreach lives only in `src/lib/afbiOutreach.ts`; every claim creator calls `assertNotAfbiSource` (`afbiGuard.ts`) and chart links go only through the Patient matching queue. Why: AFBI can never become a Medi-Cal claim or auto-merge.
- Funding source + care continuum category are stamped by rule only in `src/lib/serviceClassification.ts` (store sweep on every change), overridden only via `runAction("service_classification_override")`. Why: one rule, audited overrides.
- Every outbound path carrying Part 2 content (HIE share, note PDF, record print, document download/advocate share, legal disclosure, referral-out, DMC-ODS CSV) calls `disclose()` in `src/lib/part2Disclosure.ts`. Why: one consent check, one draft notice, one content-free disclosure log.
- Chart read events go only through `recordView` in `src/lib/accessLog.ts` (5-minute collapse). Why: one prototype access log, no content.
- Note signing clocks live only in `src/lib/noteClock.ts` (3 business days standard, 1 calendar day crisis). Why: queue, workspace and coordinator pool share one draft rule.
- Crisis escalations get a named owner in `flagCrisis` via `resolveCrisisOwner`; handoffs only via `handOffCrisisEscalation` through `runAction("crisis_handoff")`. Why: named accountability, audited, pool fallback.
- Booking rights (who books/reschedules/cancels, on whose calendar) live only in `src/lib/bookingRights.ts`, enforced inside `bookAppointment` / reschedule / cancel whenever `bookedBy` / an actor is passed; the one "Book a visit" drawer (`BookVisitDrawer.tsx`, opened via `openBookVisit`) reads `bookingFlow.ts`. Why: actor, patient and target calendar are separate and an empty calendar can never be booked.
- County reporting (CalOMS, DATAR, ISL, BHOATR, TPS, submissions, errors, reminders) lives only in `src/lib/countyReporting.ts`; `exportIslReport` delegates to it via `registerIslExportBuilder`. Why: one Part 2 gate (client rows only for `roleSeesAsam`, every file through `disclose()`), cohort-11 suppression, all county responses Simulated.
- Outpatient nursing (clinic-administered order chain, specimens, triage, refill coordination) lives only in `src/lib/nursing.ts`: prescriber orders → RN `nurseReviewOrder` → RN/LVN `administerClinicDose` (LVN routes to a supervisor cosign). Why: one store-enforced chain; nurses never prescribe and never see therapy notes; no in-facility MAR.
- Nurse (RN) / LVN record-class grants live in `NURSE_GRANTS` (roles.ts); staff are added only via `addStaffMember` (sys_admin, audited). Why: one reviewable grant table and no direct roster edits.
- External Care Partners live only in `src/lib/carePartners.ts`: the org's cluster fixes the data slice, links need consent, clinical-handoff handoffs go through `disclose()`, log keeps class names only, SUD links hidden via `roleSeesAsamSection`. Why: staff-facing only, Part 2-safe.
- The methadone guard lives only in `src/lib/methadoneGuard.ts`, enforced in `addDraftOrder` / `signOrders` / `prescribeMedication`; the offered path is `src/lib/ntpReferral.ts` (NTP referral + outside-NTP reconciliation, never an order). Why: methadone for OUD is NTP-only.
- The county hub's interim CalOMS/TPS preparer is the single constant `COUNTY_INTERIM_PREPARER_ROLE` (countyReporting.ts). Why: one-line change when decided.
- The AI scribe (consent, capture gate, draft-in-chart, provenance, retention, metrics) lives only in `src/lib/scribe.ts` behind the `ScribeAdapter` in `src/lib/vendors/scribe.ts`; every mutation is a `scribe_*` registry action, and AI drafts are signed only after open + unsupported sentences resolved + review confirmed (store gate in `signProgressNote`). Why: production swaps only the adapter.
- Scribe setting (telehealth/clinic/field), pause, offline gate, post-encounter dictation and AFBI-target drafts live in `scribe.ts`; the counsel question "does dictation need patient consent" is the single `DICTATION_REQUIRES_PATIENT_CONSENT` flag; segment ingestion (`ingestScribeSegments`) is the simulated stream, not a registry action. Why: one gate for every setting and a one-line change for counsel's answer.
- Contact-role dictation (peer, CHW, ECM, care manager) is limited to visits where the actor is `assignedStaffId` or rendering clinician, and AFBI dictation to the recording staff (`ownsAfbiContact`); enforced in `scribe.ts`. Why: the store check is the registry gate, so no UI can bypass it.
- Task-assignment notifications for SUD-related tasks use neutral text (`_TASK_PART2_RE` in `ehr.ts`). Why: notification text must never carry Part 2 content.
- Clinical-note bodies for metadata-only roles (`therapy_notes` = "summary") are gated only by `noteBodyRestricted` / `redactNoteBodies` in `roles.ts`; every note read path calls them. Why: one rule for chart, PDF, print, Adel and scribe.
- The Adel Brief (four fixed sections, cache per patient × role-visibility class, source→section invalidation, Simulated narrative) lives only in `src/lib/adelBrief.ts` + `vendors/llm.ts`; UI reads via `peekAdelBrief`. Why: instant render, incremental refresh, Part 2 never shared across roles.
- Every Adel Brief bullet carries `sources` (exact record refs); `src/lib/adelBriefCheck.ts` independently re-derives each bullet from those records through the role-filtered chart views and is the consistency gate (unit test + dev `__adelante.checkBrief()`). Why: bullets can never drift from the chart or show a role something its chart section hides.
- Adel Brief events live in the existing record-access log: `brief.viewed` via `recordBriefView` (5-minute collapse) and `brief.section_computed` as content-free system events written with `_recordAuditQuiet`. Why: one access trail; quiet writes keep the cache from re-triggering itself or updating React mid-render.
- ASAM → care-plan suggestions live only in `src/lib/asamCarePlan.ts` (drafted from the latest final ASAM, accepted/edited/dismissed/reviewed via registry `asam_plan_suggestion`); accepted goals are SUD-classified structured goals. Why: the clinician decides, provenance is kept, and Part 2 masking reuses `staffPlanView`.
- Re-screen severity flags: thresholds and the action window only in `severityRules.ts`; `recordScreener` and `recordHistoricalScreener` both call `_applySeverity` in `ehr.ts` (date-ordered, idempotent per key@completedAt; older than the window or during module-load seeds → history only). Owner = primary clinician else prescriber gets the row + neutral staff notification; prescriber gets FYI only with an active non-SUD order. Review via `severityFlags.ts` (registry `severity_flag_review`). Why: one draft config, no task floods, Part 2-neutral text.
- The Escalations queue reads every pathway (crisis, social-need, score change, overdue crisis note, missed handoff, in-facility refusal) only through `src/lib/escalations.ts`; acknowledge / hand off / reassign are registry actions that delegate crisis rows to the crisis store and keep a small overlay for the rest. Why: one view model, source stores and their rules never change.
- Staff-to-staff threads live only in `src/lib/staffThreads.ts` (patient scope, SUD-thread block, mentions → "Reply needed", neutral no-preview notifications, content-free audits); `/crisis-queue` only redirects to `/escalations`. Why: patients/advocates never reach staff threads and every mutation is registry-run.
- Patient Adel chats are saved only in `src/lib/adelHistory.ts`, keyed by owner (patient or advocate link) with no staff read path; sharing sends a Simulated topic-only summary to the care-team thread, through `disclose()` when the thread is Part 2-classified. Why: staff never see raw chats, and the crisis scan in AdelChat stays first and unchanged.
- Working days (site closed days, weekly open hours, staff hours per site, time off) live only in `src/lib/workingCalendar.ts`, extending the ehr-ext availability model; every business-day count (note clock, booking) calls it, and signed work reads it "as of" its close time. Why: one calendar rule, history never moves.
- The "outside standard hours" booking warning reads `fitsStaffHours` (workingCalendar.ts): site time zone + the clinician's hours at that site. Why: never the device clock.
- Dashboard/report tiles never render a bare literal number; intake velocity is `intakeVelocityMedian` in `referralFunnel.ts` (cohort-guarded, referral → first ATTENDED session), and every other metric is wired to a store/config source or visibly labelled "Simulated sample"; enforced by `noMockDashboardNumbers.test.ts`. Why: `/admin` once hardcoded "2.4 days" and nobody noticed.
- Screener save/resume (partial answers, never scored, never in `screenerHistory`) lives only in `src/lib/screenerDrafts.ts`; the same crisis trigger as the scored path fires on save via the existing `AdelanteEHR.flagCrisis`, once per draft, and drafts over `SCREENER_DRAFT_DAYS` expire to a content-free audit stub. Why: pausing a screener can never hide a safety signal or create an unsigned score.
- Staff add/role-site change/deactivate/reactivate live only in `src/lib/staffLifecycle.ts` (sys_admin only, reason required, audited); deactivated people are filtered out of the persona switcher, booking (`eligibleClinicians`/`availableSlots`), coordination reassignment (`eligibleReassignTargets`, `assertAssignableStaff`) and the case-manager assign picker. Why: one audited write path, no picker can surface someone already removed.
- §B4 — MAT is never conditioned on counseling attendance. No medication path (ordering, refills, MAR administration, MAT continuity alerts in medContinuity.ts) may read appointment, group or counseling attendance; `medContinuity.test.ts` fails if one does.
- §B1/B2 — MAT continuity (medContinuity.ts) and coverage at release (coverageRelease.ts) thresholds live in one Draft config each; they never block, never auto-order; task/escalation/notification text carries no medication name; coverage eligibility checks are Simulated.
- Content "what this addresses" tags, Draft backfill and every tag-driven suggestion (care plan, ASAM-free picker, patient Adel, needs "Learn more", coverage) live only in `src/lib/contentTags.ts`; publish sign-off and the Spanish block live only in `contentGovernance.ts → publishBlocker`. Why: suggestions come from tags, never hardcoded ids, and one rule decides who may publish clinical / Part 2 content.
- Community resources have one store: `listResources()` overlays the CMS working body, and `verifyResource` stamps that managed revision. Why: Verify can never overwrite edits made in the content center.

## Patient theme
Patient lessons, exercises, recovery and toolkit screens use `.patient-theme`; staff screens keep their own tokens and Fraunces headings. Use semantic primary/foreground/accent tokens (cream, deep teal, sage and amber), Inter semibold headings, body text at least 17px with 1.6 line-height, rounded-3xl soft-shadow cards and pill buttons with 44px minimum tap targets. Keep visited-only accessible progress. Respect reduced motion. All patient copy uses EN/ES i18n (Spanish Draft); voice is Simulated and opt-in. Engagement answers/supports/today-actions remain patient-only; cohort/advocate projections never include them.
- Chart entry and patient search decide only through `chartEntryFor` / `searchablePatientsFor` in `src/lib/chartAccess.ts` (role + enrolled-site rule, restricted records); `navGuard.resolveChartRouteAccess` gates /record and print. Why: one Draft access rule for route, search and deep links; sections stay gated by the record-class matrix.
- Bell vs My work: tasks live in My work; the bell gets at most one pointer per task (`taskKey`), closed by `closeTaskPointer` / `syncBellPointers` (`notificationRouting.ts`); role broadcasts track `readBy` per person. Why: no duplicates and one reader never clears it for others.
- Screener drafts read through `syncFromSession()` on every get/save/list/discard (`screenerDrafts.ts`). Why: a second module copy after a dev reload must see answers saved by the first.

- No module-level timers, random values, or async I/O: the published server runtime forbids them at import time and every page 500s. Seed-quiet windows end via explicit end*() calls (e.g. endSeveritySeedQuiet) at the end of seedDemoInbox, never setTimeout. Why: workerd global-scope restriction crashed the live site (Oct 2026).
- Patient pathway (general / reentry / sud / reentry_sud) is derived only by `patientPathway` / `pathwayFromFlags` in `src/lib/flagJourneys.ts` from `detectFlags`; auto-added journeys come from `journeysForPathway` (content `meta.pathways` + `meta.pathwayOrder`), Adel's prompt/actions take an `AdelAudience` from it, and the staff chip hides the SUD half via `roleSeesAsamSection`. Why: one value for journeys, Adel and chips; rule changes mark items "Pathway changed — review", never remove.
- Referral enrollment, HIE match confirmation (`confirmMatch`, sud_program only) and intake/problem list are the only pathway-flag writers; each records `Patient.flagSources` for the audit reason. Why: flags land at identification and the reason always matches the rule.
- Staff consent-ledger purpose toggles go only through `consent_purpose_set` → `AdelanteEHR.staffSetConsent` (consent_ledger write roles, actor recorded); patient self-service stays on `setConsent` / `patientWithdrawConsent`. Why: role-gated in store and UI, audited with the real staff member.
- Emergency contacts and the advocate are separate records linked by `AdvocateLink.contactId` + `contactSnapshot`; lists, validation and status live in `src/lib/contactAdvocate.ts`, patient advocate consent only through the versioned `advocate_patient` form in `consentForms.ts` (signing it releases held invitations). Why: no silent divergence — drift shows an "update advocate?" prompt.
- Consent forms (library, versions, send, sign, decline, signed copies, revoke, renewal, intake packet, group gate) live only in `src/lib/consentForms.ts`; staff writes go through `consent_form_*` actions, signing writes a superseding ConsentRecord, signed copies are frozen and never deleted. Why: one ledger, version-true signatures, Draft — pending counsel review.
- Group booking checks `groupConsentBlock` (registered by consentForms into ehr.ts) only for patients whose packet requires Group participation; medication/MAT paths never read it. Why: declining group never blocks individual care or MAT.
- A booking freeze (`bookingsFrozen`) removes every open slot in `availableSlots`. Why: frozen calendars must not be offered.
- Browser walkthroughs reach app modules through `window.__adelante.avail()` / `content()` / `access()`, never bare "/src/..." imports. Why: bare imports can load a second module instance with separate in-memory state.
- Advocate consent has one path: the versioned `advocate_patient` form in Forms to sign; `AdvocateConsentStatus` only shows status and links there. Signing it writes `roi_collateral` and triggers invite delivery; the advocate's claim signs `advocate_attestation`. Why: no second, unversioned signing path.
- Demo seeds never leave a demo persona frozen; freeze tests use a test-only clinician id. Why: demos must be able to book every persona.
- Browser specs must wait for the target screen to render (not just the URL) before navigating again. Why: under load the URL changes before the router commits the new screen, so a quick return lands on the still-mounted old one.
